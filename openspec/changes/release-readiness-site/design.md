## Context
用户授权修复发布检查项并新增官方页；已指定oss-release-prep，其官方页约定采用gruvbox黑金与双语交互。现有主文档中文，源码与终端工作未提交，不能覆盖。GitHub账号已核实，目标仓库暂无。

## Goals / Non-Goals
**Goals:** 本地修复隐私与快照完整性；单文件离线可打开官方页；真实浏览器可验收；提供准备好的发布配置。
**Non-Goals:** 不改变Agent运行时、不引入前端框架、不虚构模型成功、无授权不创建公共仓库/托管。

## Decisions
- 指定视觉系统作为已有设计授权：背景#1d2021/#282828、金色#d79921、暖白#fbf1c7；8px间距、小圆角、细边界；Space Grotesk/JetBrains Mono字体栈与本地回退，无字体请求。新建官方页，变动/动效/密度/素材/品牌忠实度=4/3/6/2/9。面向开发者桌面与移动近距离阅读；首屏说明定位、安装入口，终端与流程承担技术叙事。
- 单文件HTML/CSS/JS：默认中文、EN切换含所有动态内容、命令展示、原生details目录、五段请求流程、Tweaks颜色/动效、尊重系统减少动效、真实SVG截图内嵌。无额外运行时依赖。
- CLI没有定时任务，官网不展示虚构日程；仅显示本地时钟和按需执行事实。打字终端与迷你命令台标为用法演示，只有实际版本输出，不模拟业务结果。
- Git本地历史仅替换未发布初始提交身份，保留树和消息；修改前bundle和工作树备份放项目外。使用已确认账号的公开noreply身份；后续完整提交包含已验收文件。不保留含私密身份的可推送备份ref，不自动清理reflog/不可达对象。
- 元数据填写明确的目标仓库/主页URL，文档注明未上线；安全通道先给现有GitHub账号的真实私信联系方式页面，不编造邮箱，发布后启用Private Vulnerability Reporting。新建仓库授权在本地产物准备后再处理。
- 新增发布预检脚本：工作树/可达历史内容扫描、Git身份、未跟踪源码检查；可发布提交要求干净工作树。测试需覆盖真实失败和通过状态，工具只输出位置/规则不输出敏感值。

## Risks / Trade-offs
- 目标仓库/Pages未建立 → 页面明确待发布，外部上线门禁保留待执行，不宣称链接已在线。
- 本地历史重写 → 外部bundle和工作树备份；保持原tree；不推送，私密旧对象仍可能在本地reflog中，不能直接分享.git目录。
- 无内置私密反馈系统 → 给出真实联系账号，明确禁止公开发送秘密；仓库存在后应启用并实际验证私密报告。

## Migration Plan
本地修复与测试后生成完整提交；干净检出离线构建安装；发布需要用户确认目的仓库与公开托管。回滚源码可用任务前工作树归档，本地历史可从外部bundle恢复。
